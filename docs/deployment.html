Deployment

Four ways to reach the panel, from a laptop to a public domain — and the one setting that decides whether your rate limiting is real.

The panel binds to 127.0.0.1 and nothing else. That is not a default waiting to be changed: it grants full RCON access to whoever signs in, so making it reachable should be a decision you take on purpose. Every recipe below keeps the container on loopback and puts something in front of it.

TRUST_PROXY is not cosmetic Login attempt limiting is per IP. Without TRUST_PROXY=true the panel ignores X-Forwarded-For — deliberately, because a forgeable header must not drive rate limiting — so the per-IP limiter is skipped entirely and only the global cap is left standing (src/server/http/context.ts). With it set behind a proxy that does not overwrite the header, an attacker picks their own identity and the limiter is bypassable. Set it only behind a proxy you control that rewrites the header itself. All four recipes below do.

Local, on your own machine#

Nothing in front, nothing to configure. This is the quickstart, and it is also the right answer for a server you administer over SSH — forward the port instead of publishing it.

docker compose up -d
# → http://127.0.0.1:3010

# From another machine, without exposing anything:
ssh -N -L 3010:127.0.0.1:3010 you@your-server

Caddy#

The shortest path to HTTPS: Caddy obtains and renews the certificate on its own, and sets X-Forwarded-For itself.

factorio.example.com {
    reverse_proxy 127.0.0.1:3010
}

Then add the variable to the factorio-admin service:

environment:
  - TRUST_PROXY=true

Nginx#

The proxy_set_header lines are the point: Nginx passes an inbound X-Forwarded-For through unless you overwrite it, and $proxy_add_x_forwarded_for appends rather than replaces. Setting it to $remote_addr discards whatever the client claimed.

server {
    listen 443 ssl http2;
    server_name factorio.example.com;

    ssl_certificate     /etc/letsencrypt/live/factorio.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/factorio.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3010;
        proxy_set_header Host              $host;
        proxy_set_header X-Forwarded-For   $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

Traefik#

With Traefik on a Docker network of its own, drop the port publishing entirely, add that network to the panel and label the service. Traefik writes X-Forwarded-For itself for any client that is not in trustedIPs.

services:
  factorio-admin:
    # No `ports:` at all — Traefik reaches the container over the network.
    # Listing networks replaces the compose file's list: keep the two the
    # panel needs, then add Traefik's.
    networks:
      - game
      - control
      - proxy
    environment:
      - TRUST_PROXY=true
    labels:
      - "traefik.enable=true"
      # The panel sits on three networks: tell Traefik which one to use.
      - "traefik.docker.network=proxy"
      - "traefik.http.routers.factorio-admin.rule=Host(`factorio.example.com`)"
      - "traefik.http.routers.factorio-admin.entrypoints=websecure"
      - "traefik.http.routers.factorio-admin.tls.certresolver=letsencrypt"
      - "traefik.http.services.factorio-admin.loadbalancer.server.port=3000"

networks:
  proxy:
    external: true
Never attach Traefik to control That network is how the panel reaches the agents, and it is internal precisely so that nothing else does. Traefik joins the panel through its own network, and only the panel's.

Tailscale#

The option with the smallest attack surface: no public port, no certificate to renew, no reverse proxy to keep patched. The panel is reachable from your tailnet and from nowhere else, which suits an admin console better than a public hostname does.

# On the host running the stack
tailscale serve --bg --https=443 http://127.0.0.1:3010

# → https://your-host.your-tailnet.ts.net
tailscale serve status
TRUST_PROXY here too tailscale serve terminates TLS and forwards over loopback, so it is a reverse proxy like the others: set TRUST_PROXY=true, or every tailnet client shares one rate-limit bucket. Do not use tailscale funnel unless you mean to publish the panel to the whole internet.

Outbound access#

Only one container of the stack talks to the Internet on the panel's behalf: the data agent, to search the mod portal and download mods. If the host sits behind an egress firewall, it needs:

DestinationPortFor
mods.factorio.com443/tcpSearch, mod pages, update checks
dl-mod.factorio.com443/tcpDownloads (the portal redirects there)

The agent refuses any other host, redirects included, so opening more buys nothing. The panel and the control agent need no outbound access at all. The game server has its own needs, unrelated to the panel: the public server list, and the image's own updater if you turn it on.

Behind an HTTP proxy, give the data agent the standard variable; Go honours it:

  data-agent:
    environment:
      - HTTPS_PROXY=http://proxy.internal:3128

Backups off the host#

Archives land in ./backups, deliberately outside ./data, so that a copy elsewhere is one folder, not a selection. Each archive is a zip plus a JSON sidecar that describes it, so a copy is useful on its own. Use whatever you already run:

# A nightly copy, as the archives' owner (uid 845) or root
rsync -a --delete ./backups/ backup-host:/srv/factorio-backups/

# Or a deduplicated, encrypted repository
restic -r sftp:backup-host:/srv/restic backup ./backups

Two folders inside it are the agent's own: replaced-<time>/ holds the saves a restore replaced, and .mods/ the last mod transactions. Copy them too or leave them out; nothing depends on them elsewhere. The panel's own volume, factorio-admin-data, holds the audit log and the backup schedule, not the archives.

Checking it worked#

# Readiness: config, catalogue, database and RCON; plus the control agent when
# server control or Docker metrics are enabled, and the data agent when saves
# or mods are. One object per check.
curl -s https://factorio.example.com/api/ready | python3 -m json.tool

# The cookie must come back Secure over HTTPS.
curl -si https://factorio.example.com/api/login \
  -H 'Content-Type: application/json' -H 'Origin: https://factorio.example.com' \
  -d '{"password":"wrong"}' | grep -i set-cookie

A failed login should answer 401, and repeated attempts should start answering 429. If they never do, the panel is not seeing distinct client addresses — re-read TRUST_PROXY above.
