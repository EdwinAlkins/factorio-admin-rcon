HTTP API

The routes the panel exposes, their access control and the shape of their errors.

Every route lives under /api and answers JSON. Most authenticate with the session cookie; sign-in and the liveness/readiness probes are public, as shown below. The routes are usable from curl: a request with no Origin header is accepted, since it did not come from a browser and therefore cannot be a CSRF attack.

Signing in#

curl -sc cookies.txt \
  -H 'Content-Type: application/json' \
  -d '{"password":"your-admin-password"}' \
  http://127.0.0.1:3010/api/login
# {"ok":true,"username":"admin","role":"admin"}

curl -sb cookies.txt http://127.0.0.1:3010/api/status

Running an action#

The body only carries an id and values. The server builds the command.

curl -sb cookies.txt \
  -H 'Content-Type: application/json' \
  -d '{"action":"kick","values":{"player":"bob","reason":"spam"}}' \
  http://127.0.0.1:3010/api/actions

A custom command is called by its prefixed id:

curl -sb cookies.txt \
  -H 'Content-Type: application/json' \
  -d '{"action":"custom:kill-enemies","values":{"player":"Edwins"}}' \
  http://127.0.0.1:3010/api/actions

Controlling the server#

The state endpoint is available to every signed-in role. Logs and mutations are restricted to the administrator. A start, stop or restart is asynchronous: the route answers 202 with the operation, and GET /api/server exposes its progress and recent history.

# Container + game state
curl -sb cookies.txt http://127.0.0.1:3010/api/server

# Last 200 log lines (1 to 1000)
curl -sb cookies.txt 'http://127.0.0.1:3010/api/server/logs?tail=200'

# Start with no options; an empty body is accepted
curl -sb cookies.txt -X POST http://127.0.0.1:3010/api/server/start

# Stop after saving. If players are online or RCON is unavailable, the first
# request returns 409; repeat explicitly with force only after confirmation.
curl -sb cookies.txt -X POST \
  -H 'Content-Type: application/json' \
  -d '{"force":true}' \
  http://127.0.0.1:3010/api/server/stop
force bypasses two safety checks It allows stop or restart while players are connected, or while RCON is down and the panel cannot request a save first. It does not bypass permissions, the operation lock or the control agent.

Saves#

Moderators read the list; everything else is for the administrator. Creating and restoring are operations, like a start or a stop: 202, then progress through GET /api/saves or GET /api/server. Archive ids come from the listing (20261027-143000-manual); no route takes a path.

# Saves folder, archives, schedule
curl -sb cookies.txt http://127.0.0.1:3010/api/saves

# Archive now, with a label
curl -sb cookies.txt -X POST \
  -H 'Content-Type: application/json' \
  -d '{"label":"before the train rework"}' \
  http://127.0.0.1:3010/api/saves

# Download
curl -sb cookies.txt -OJ \
  http://127.0.0.1:3010/api/saves/20261027-143000-manual/download

# Restore. 409 restore_incompatible or players_online first; repeat with
# force only after confirmation.
curl -sb cookies.txt -X POST \
  -H 'Content-Type: application/json' \
  -d '{"force":true}' \
  http://127.0.0.1:3010/api/saves/20261027-143000-manual/restore

# Schedule: every 2 hours, keep 24 and at most 7 days, archive the autosave
curl -sb cookies.txt -X PUT \
  -H 'Content-Type: application/json' \
  -d '{"enabled":true,"intervalMinutes":120,"keepLast":24,"maxAgeDays":7,"triggerSave":false}' \
  http://127.0.0.1:3010/api/saves/settings

force on a restore overrides the game version or mod set mismatch, and players online or RCON down. It never overrides the checksum: a damaged archive is refused (422) before the server is touched.

Mods#

Every role reads the list; the rest is mods:manage, the administrator's. A change is a basket of up to 50 entries, each an action (install, update, enable, disable, remove), a mod name and, for an install or an update, an optional version. Without one, the newest release that fits is chosen.

# Installed mods, updates, game version
curl -sb cookies.txt http://127.0.0.1:3010/api/mods

# Search the portal (needs credentials)
curl -sb cookies.txt 'http://127.0.0.1:3010/api/mods/search?q=squeak&page=1'

# Preview: steps, dependencies pulled in, conflicts, and a hash
curl -sb cookies.txt -X POST \
  -H 'Content-Type: application/json' \
  -d '{"changes":[{"action":"install","name":"Squeak Through"}]}' \
  http://127.0.0.1:3010/api/mods/plan

# Apply exactly that plan: the same changes, and its hash
curl -sb cookies.txt -X POST \
  -H 'Content-Type: application/json' \
  -d '{"changes":[{"action":"install","name":"Squeak Through"}],"planHash":"<hash from the plan>"}' \
  http://127.0.0.1:3010/api/mods/apply

The plan answers steps (each with action, name, from/to versions, and requiredBy when a dependency pulled it in), conflicts, optional dependencies not installed, mods whose info.json could not be read (unchecked), and the hash. An apply is refused if the plan has conflicts, nothing to do, or a different hash than the one sent: preview again. force on an apply overrides players online and RCON down, nothing else.

Error format#

An error always carries the same envelope. code is the translation key and is authoritative for the interface; error is only an English fallback, readable for whoever calls the API from a shell.

{
  "ok": false,
  "error": "player: invalid player name (no spaces or quotes, 60 max).",
  "code": "validation_player",
  "params": { "field": "player" }
}

HTTP statuses#

StatusWhen
400Malformed body, or input rejected by validation
401No session, expired, revoked, or invalid signature
403Insufficient permission, or foreign origin on a mutating request
404Unknown action or archive, mod not on the portal, or feature turned off (metrics_disabled, control_disabled, data_disabled, mods_disabled)
409Operation already running, invalid container state, players online, RCON unavailable before a save, archive from a different game, mod conflict, plan changed since the preview, no portal credentials, game version not known yet
413Request body beyond the route limit
422Archive or mod download that fails verification: checksum, structure, info.json, size
429Rate limit reached; the Retry-After header is set
500Invalid configuration, rejected agent token, or internal error
502 / 504Factorio, an agent or the mod portal is unreachable, refuses an operation, or times out
503RCON queue full, panel shutting down, or control-agent target unavailable or ambiguous
