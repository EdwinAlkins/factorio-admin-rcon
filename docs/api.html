HTTP API

The routes the panel exposes, their access control and the shape of their errors.

Every route lives under /api and answers JSON. Most authenticate with the session cookie; sign-in and the liveness/readiness probes are public, as shown below. The routes are usable from curl: a request with no Origin header is accepted, since it did not come from a browser and therefore cannot be a CSRF attack.

RouteAccessPurpose

POST /api/logoutSessionRevokes the session in the database and clears the cookie
GET /api/statusstatus:readServer status, cached

POST /api/actionsPer actionRuns a catalogue action

GET /api/auditaudit:readLatest audit entries, ?limit=

GET /api/healthPublicLiveness: the process is alive
GET /api/readyPublicReadiness: config, catalogue, database, RCON and, when required, control agent

Signing in#

curl -sc cookies.txt \
  -H 'Content-Type: application/json' \
  -d '{"password":"your-admin-password"}' \
  http://127.0.0.1:3010/api/login
# {"ok":true,"username":"admin","role":"admin"}

curl -sb cookies.txt http://127.0.0.1:3010/api/status

Running an action#

The body only carries an id and values. The server builds the command.

curl -sb cookies.txt \
  -H 'Content-Type: application/json' \
  -d '{"action":"kick","values":{"player":"bob","reason":"spam"}}' \
  http://127.0.0.1:3010/api/actions

A custom command is called by its prefixed id:

curl -sb cookies.txt \
  -H 'Content-Type: application/json' \
  -d '{"action":"custom:kill-enemies","values":{"player":"Edwins"}}' \
  http://127.0.0.1:3010/api/actions

Controlling the server#

The state endpoint is available to every signed-in role. Logs and mutations are restricted to the administrator. A start, stop or restart is asynchronous: the route answers 202 with the operation, and GET /api/server exposes its progress and recent history.

# Container + game state
curl -sb cookies.txt http://127.0.0.1:3010/api/server

# Last 200 log lines (1 to 1000)
curl -sb cookies.txt 'http://127.0.0.1:3010/api/server/logs?tail=200'

# Start with no options; an empty body is accepted
curl -sb cookies.txt -X POST http://127.0.0.1:3010/api/server/start

# Stop after saving. If players are online or RCON is unavailable, the first
# request returns 409; repeat explicitly with force only after confirmation.
curl -sb cookies.txt -X POST \
  -H 'Content-Type: application/json' \
  -d '{"force":true}' \
  http://127.0.0.1:3010/api/server/stop
force bypasses two safety checks It allows stop or restart while players are connected, or while RCON is down and the panel cannot request a save first. It does not bypass permissions, the operation lock or the control agent.

Error format#

An error always carries the same envelope. code is the translation key and is authoritative for the interface; error is only an English fallback, readable for whoever calls the API from a shell.

{
  "ok": false,
  "error": "player: invalid player name (no spaces or quotes, 60 max).",
  "code": "validation_player",
  "params": { "field": "player" }
}

HTTP statuses#

StatusWhen
400Malformed body, or input rejected by validation
401No session, expired, revoked, or invalid signature
403Insufficient permission, or foreign origin on a mutating request
404Unknown action, or feature turned off (metrics or server control)
409Server operation already running, invalid container state, players online, or RCON unavailable before a save
413Request body beyond the route limit
429Rate limit reached; the Retry-After header is set
500Invalid configuration, rejected control-agent token, or internal error
502 / 504Factorio or the control agent is unreachable, refuses an operation, or times out
503RCON queue full, panel shutting down, or control-agent target unavailable or ambiguous
